# 本人用リンク：変更要件（案）

状態：**設計案。ユーザー確認前で、全体要件（`docs/requirements_definition.md`）にはまだ反映していない。** 確認後に要件書と `AGENTS.md` を同じ変更で更新してから実装する。

## 背景

- 支援の始めは、窓口役（主催者。夫・パートナー、実母、友人など）が本人の了承と希望を確認してページを作る。
- 途中からは、体調が悪くて食事を作れない、おむつが足りないなど、**本人にしか分からない困りごと**が出てくる。窓口役を通すと伝言だけの役になり、急ぎのお願いが遅れる。
- 本人は遠慮しやすい。自分から「頼む」負担を減らし、ありがた迷惑を防ぐ必要がある。

## 目的

本人が、アカウントを作らずに、困りごとをそのまま予定（お願い）として出せる。窓口役と支援者は、今の担当の流れのまま対応できる。

## 利用者と権限

| 利用者           | 追加される権限                                                                                                                   |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 窓口役（主催者） | 本人用リンクの発行・再発行・無効化。本人が出したお願いの確認・編集・削除（今の予定と同じ規則）                                   |
| 本人             | 本人用リンクで、お願いの追加、まだ担当が決まっていない自分のお願いの取り消し、受付の一時停止・再開、ページの予定と担当状況の閲覧 |
| 支援者           | 変更なし。本人が出したお願いも、今の予定と同じように担当・キャンセルできる                                                       |

本人ができないこと：ページの公開・非公開・終了・削除、パスコードの変更、窓口役が作った予定の編集、支援者のメールアドレスや主催者向けのひとことの閲覧、本人用リンクの再発行。

## 機能要件

### R1 本人用リンク

- 窓口役がダッシュボードで発行し、コピーまたはLINEで本人に送る。
- 256bit以上のランダムトークン。DBにはSHA-256ハッシュだけを保存する。担当管理トークンとは用途を分け、流用しない。
- 1ページに有効なリンクは1つ。再発行すると以前のリンクは即時に無効になる。窓口役は無効化もできる。
- ページの削除・終了で無効になる。
- 本人用ページは noindex・nofollow、Cache-Control private,no-store、Referrer-Policy no-referrer。サイトマップに載せない。

### R2 お願いの追加

- 定型ボタンから選ぶ：「今日のご飯」「おむつ・日用品の買い物」「上の子の送迎」「家事」「その他」。選ぶと、カテゴリと公開用の予定名が自動で入る。
- 入力は最小限：日付（既定は今日）、時間帯（任意）、ひとこと（公開、任意）、担当した人にだけ伝えること（非公開、任意。例：おむつのサイズ・枚数、置き場所）。
- **公開する予定名・説明には体調や健康の理由を入れない。** 定型の予定名は中立的にする（例：「夕食を届ける」。「体調不良のため」とは書かない）。公開欄の近くに「体調のことは書かなくて大丈夫です」と案内する。
- 支援期間内、1ページ60枠以内に限る。期間外の日付は、窓口役に期間延長を頼むよう案内する。
- 窓口役の承認なしで、そのまま公開する（急ぎのお願いに間に合わせ、本人の遠慮を増やさないため）。ページが公開中でない場合は追加できない。
- 予定・お願い元・計測・窓口役への通知を同じトランザクションで確定する。

### R3 お願いを知らせる

- 追加後に「LINEで知らせる」「リンクをコピー」を表示する。送る文面は日付・予定名・公開ページURLだけで、非公開の内容を含めない。
- 窓口役へ通知outboxでメールを登録する（支援通知が未接続の間は配信済みと表示しない）。ダッシュボードには「本人が追加したお願い」と分かる表示を出す。
- 「新しい予定ができた」ことを支援者全員にメールで一斉通知する機能は今回は作らない（支援者のメールは任意で、一斉通知はPlusの候補のため）。

### R4 取り消し

- 本人は、自分が出したお願いのうち、担当がまだ決まっていないものを取り消せる。
- 担当が決まったお願いは、本人からは取り消せない。「担当の方か窓口役に連絡してください」と案内する（今の「担当確定済み予定は変更・削除を拒否」と同じ）。

### R5 一時停止（お休み）

- 本人と窓口役が、受付を一時停止・再開できる。停止中は新しい担当を受け付けず、公開ページに「ただいまお休み中です」と表示する。すでに決まった担当はそのまま。
- 窓口役の「非公開」とは別の状態にする。終了したページでは使えない。

### R6 ありがた迷惑を防ぐ配慮（同じ画面で扱う）

- 本人用ページに「お願いは気軽に。お返しやお礼の連絡は不要です、と支援者に伝わっています」と表示する。
- 公開ページに表示する配慮の定型文（お返し不要、置き配のみ、長居しない、返信不要）を窓口役が選べる。本人も変更できる。

### R7 お金

- 買い物の立て替えは当事者同士で扱う。アプリは精算・送金を扱わない。買い物のお願いに「お代のやり取りはご本人と直接」と表示する。

## 対象外（今回）

- 本人の希望確認シート（作成前に本人から希望を集める仕組み）。本人用リンクの上に後から追加する。`design.md` の「後続」を参照。
- 本人のFirebaseアカウント、共同管理者（co_organizer）の有効化。
- 支援者への一斉通知、SMS、LINE公式アカウント・ミニアプリからの送信。
- 本人による担当者への直接連絡（DM）。

## 受け入れ条件（案）

| ID    | 条件                                                                                                                                            |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| RA-01 | 本人用リンクを持つ人だけが、そのページにお願いを追加できる。別ページのお願い・予定を操作できない。再発行・無効化した古いリンクでは何もできない  |
| RA-02 | 本人のお願いは公開ページにすぐ表示され、支援者が今の流れで担当・キャンセルできる。1枠1人を保つ                                                  |
| RA-03 | 本人用ページ・本人用API・LINE共有文面に、支援者のメール、主催者向けのひとこと、管理トークンを含めない。公開レスポンスに非公開欄の内容を含めない |
| RA-04 | 窓口役が古い画面のまま保存しても、本人が追加したお願いが消えない（競合を検出して読み込み直しを求める）                                          |
| RA-05 | 担当が決まったお願いは、本人から取り消せない                                                                                                    |
| RA-06 | 一時停止中は新しい担当を受け付けず、決まった担当は残る                                                                                          |
| RA-07 | お願い追加・取り消し・一時停止の計測と窓口役への通知が、状態変更と同じcommitで確定する。計測に個人情報を含めない                                |
| RA-08 | 375/390/430pxで、本人がリンクを開いてから「今日のご飯」を出し、LINE共有を開くまでを確認する                                                     |
