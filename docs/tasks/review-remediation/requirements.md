作成日：2026-10-12。状態：R1〜R4の実装・ローカル検証済み。PR #7マージ・本番デプロイ済み。本人用機能フラグはOFF。

## 目的・正本

2026-10-12の[コードレビュー](../../code-review-2026-10-12.md)で確認したR1〜R4を解消し、作成・編集・公開・担当・キャンセルと本人用機能を検証できる状態にする。

全体要件は [共通要件定義書](../../requirements_definition.md)、運用ルールは [AGENTS.md](../../../AGENTS.md)。本書は今回の修正範囲と受け入れ条件を記述する。設計は [design.md](design.md)、実績は [tasklist.md](tasklist.md) を参照する。

## 対象と前提

- 現在のルートには未コミット・未追跡の変更があり、レビュー時のHEADは `030bb0937c8776d4fac4482400b943ff36da1375`。引き継ぎには別チェックアウトでのマージ・PR・検証の記録もあるため、実装開始時に実際の `origin/main` と対象PRの差分を照合する。
- 取り込み済みの修正を再実装せず、基準コードを整合させた後に残る不具合を修正する。既存の作業ファイルをリセット・上書きしない。
- LINE通知受信とログイン完了はユーザー確認済み。今回の修正では認証方式や通知プロバイダーを変更しない。
- ご本人用機能は既定OFFを維持し、ローカルテストでON/OFFを確認する。

## 修正要件

| ID | 対象 | 修正後の条件 |
| --- | --- | --- |
| RR-01 | R1：依存・型・設定 | 本人用サービス、テンプレート、定型、型、契約、フラグが一致し、型チェック・ビルドが成功する。型エラーの抑制で回避しない |
| RR-02 | R1：画面・非公開境界 | ONで主催者が本人用リンクを管理でき、お休み・定型が公開画面へ反映される。OFFでは本人用URL/APIを404とし、管理UIを表示しない。本人用URLのnoindex/no-store、robots除外と非公開項目の非露出を保つ |
| RR-03 | R2：通常保存 | 詳細編集は編集開始時の `baseRevision` を送り、版が一致した通常保存に成功する。既存ページの未保存revisionは0として扱う |
| RR-04 | R2：競合保存 | 古い版の保存は409で拒否し、カレンダー追加や本人による追加・取り消しを消さない。版が欠落・不正な保存は拒否する。サービスの直接呼び出しでも版検証を省略できない |
| RR-05 | R3：終了後のリンク | 手動終了、期間終了、削除、無効化、再発行後の旧リンクは、本人用の表示・追加・取り消し・設定変更に使用できない。期間終了はCron実行前でも拒否する |
| RR-06 | R4：最終1件 | 公開中の最後の予定を本人が取り消そうとした場合は409で拒否し、予定・非公開情報・revision・計測を変更しない。ページ状態を自動変更しない |
| RR-07 | R4：正常・同時取り消し | 複数件あるときは担当前の本人のお願いを取り消せる。同じ成功済み取り消しの再送は冪等。最後の2件への同時取り消しでも公開中に1件以上残り、担当登録との競合で確定済み予定を消さない |
| RR-08 | 操作案内 | 最終1件の取り消しを画面でも防ぎ、「最後の予定のため、このまま取り消せません。ページを作った方に相談してください」と案内する。画面が古い場合はサーバーの409を表示する |
| RR-09 | 既存機能 | 0件の下書き、カレンダーの単日・複数日追加、パスコード、匿名担当・キャンセル、通知outbox、管理リンク保存、公開情報の境界を維持する |

最終1件を拒否する方針は、共通要件の「公開中ページの予定は少なくとも1件残す」を本人の取り消しにも適用するもの。主催者による別予定の追加または非公開化の後に整理できる。取り消し処理から本人へ公開状態を変える権限を追加しない。
